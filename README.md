# 🎒 Чат-бот «Бюро находок» — платформа MAX

Школьный чат-бот и мини-приложение, которые собирают все потерянные вещи школы
в одном месте: объявления о находках не теряются в чатах, а владельцы быстро
возвращают свои вещи. Проект команды **«Помогаторы»** (МБОУ-лицей, Владикавказ),
трек **«Школа — это больше, чем уроки»**, направление **«Арена развлечений»**.

- Бот в MAX: **https://max.ru/ideya_fiks_66_bot**

## Что умеет (по ТЗ, слайды 7–11)

| # | По ТЗ | Как реализовано |
|---|-------|-----------------|
| 7 | Стартовое приветствие и меню («Потеряно», «Найдено») | Слово **«Старт»** или кнопка «Начать» в чате открывает приветствие и инлайн-меню |
| 8 | Кнопка «Потерянные вещи» → страница с объявлениями о найденных вещах | Кнопка «🔎 Потеряно» показывает список вещей, найденных в школе; кнопка-ссылка открывает мини-приложение **/lost** с фото |
| 9 | Кнопка «Найденные вещи» → архив вернувшихся владельцам | Кнопка «📚 Найденные вещи (архив)» и страница **/archive** с учётом по категориям |
| 10 | Форма объявления: место нахождения, фото, категория → в БД | Пошаговая форма в чате (категория → место → фото) и веб-форма **/found**; всё падает в базу данных |
| 11 | Владелец получил вещь → отмечает объявление | Кнопка **«✅ Это моя вещь — забрал!»** под объявлением (в чате и в мини-приложении) переводит вещь в архив |

Плюс: страница **/stats** — учёт, сколько вещей прошло через бюро и что теряется
чаще всего (из «Проблематики» ТЗ).

## Стек

- **Python 3.11**, **FastAPI** + **Uvicorn** — мини-приложение (HTML-страницы, формы, фото)
- **httpx** — Long Polling клиент Bot API MAX (`GET /updates` + `POST /messages`, `POST /answers`, `POST /uploads`)
- **SQLite** — база объявлений (файл `data/buro.db`, переживает перезапуск)
- **Jinja2** — шаблоны страниц мини-приложения
- Одна команда контейнера поднимает **и бота, и мини-приложение**

## 🚀 Запуск через Docker (по регламенту сдачи)

### 1) Настроить токен

```bash
cp .env.example .env
# вписать BOT_TOKEN из MAX для бизнеса:
# business.max.ru → Чат-боты → ideya_fiks_66_bot → ⋮ → Настройки → токен
nano .env
```

Токен можно получить и у бота «MAX для бизнеса» (https://max.ru/business_bot)
командой **«Получить токен»**.

### 2) Собрать образ

```bash
docker build -t buro-nahodok:latest .
```

### 3) Запустить контейнер

```bash
# через compose (рекомендуется):
docker compose up -d

# или одной командой без compose:
docker run -d --name buro-nahodok \
  --env-file .env \
  -p 8000:8000 \
  -v "$(pwd)/data:/app/data" \
  buro-nahodok:latest
```

Проверка: `curl http://localhost:8000/healthz` → `{"ok": true, ...}`

### 4) Подключить мини-приложение в MAX

1. Открой «MAX для бизнеса» → **Чат-боты** → `ideya_fiks_66_bot` → **⋮** → **Настройки**.
2. В поле ссылки мини-приложения укажи **публичный HTTPS-адрес контейнера**
   (например `https://buro.myschool.ru`), кнопка в чате бота станет запускать мини-приложение.
3. Значение этого же адреса укажи в `.env` как `WEBAPP_PUBLIC_URL` — оно используется
   в кнопках-ссылках внутри чата и на страницах.

### Пример запуска через командную строку (без Docker)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

export BOT_TOKEN="токен_бота"          # Windows: set BOT_TOKEN=...
export WEBAPP_PUBLIC_URL="http://127.0.0.1:8000"

uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Открыть в браузере `http://127.0.0.1:8000` — мини-приложение; бот начнёт принимать
сообщения через Long Polling автоматически.

## Как выглядит сценарий в чате

1. Пользователь отправляет **«Старт»** (или жмёт «Начать») → бот здоровается
   и показывает две кнопки: **«🔎 Потеряно»** и **«📦 Нашёл вещь — добавить объявление»**.
2. **«🔎 Потеряно»** → список найденных вещей: №, категория, место, фото —
   плюс кнопка перехода в мини-приложение.
3. **«📦 Нашёл вещь»** → бот по шагам спрашивает категорию → место → пришлите фото
   (или «Без фото») → объявление сохраняется в БД, бот присылает карточку.
4. Кнопка **«📚 Найденные вещи (архив)»** → что уже вернулось владельцам.
5. Владелец узнал свою вещь → жмёт **«✅ Это моя вещь — забрал!»** →
   объявление отмечается возвращённым, запись уходит в архив и в учёт.

## API мини-приложения

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | Главная и статистика |
| GET | `/lost` | Список найденных вещей (слайд 8) |
| GET | `/archive` | Архив возвратов (слайд 9) |
| GET | `/found` | Форма добавления (слайд 10) |
| GET | `/item/{id}` | Карточка объявления |
| POST | `/claim/{id}` | Отметить вещь возвращённой (слайд 11) |
| GET | `/stats` | Учёт потеряшек (слайд «Проблематика») |
| GET | `/photos/…` | Фотографии объявлений |
| GET | `/healthz` | Проверка живости контейнера |

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота из MAX для бизнеса (обязателен для бота) |
| `WEBAPP_PUBLIC_URL` | `http://localhost:8000` | Адрес мини-приложения для кнопок-ссылок |
| `MAX_API_URL` | `https://platform-api2.max.ru` | Домен Bot API MAX |
| `POLL_TIMEOUT` | `30` | Таймаут Long Polling, сек |
| `LIST_PAGE_SIZE` | `10` | Сколько объявлений в сообщении-списке |
| `TZ` | `Europe/Moscow` | Часовой пояс для дат |
| `TLS_NO_VERIFY` | `0` | Только для отладки в нестандартных сетях |

## Как мы это делали

Писали на Python, потому что так проще всего быстро запустить бот. Сначала долго
разбирались с документацией платформы MAX на dev.max.ru — она свежая, из тонкостей:

- домен для запросов поменялся на `platform-api2.max.ru`, если взять старый — всё виснет;
- токен нельзя передавать в адресе запроса, только в заголовке;
- после загрузки фото нужно немного подождать, оно «дозревает» на сервере.

Самая ошибка-ловушка для нас была с клавиатурами: кнопки в MAX живут как вложение
`inline_keyboard`, а не отдельным полем сообщения. И с датами — пришлось
привыкать хранить время в Unix-формате и выводить в московском поясе.

Кто что делал: хранением объявлений занимался Артур, чат-сценарии — Тимофей и
Руслана, страницы мини-приложения — Саша и Амина. Тестировали на своих телефонах
в групповом чате класса.

## Замечания

- Long Polling — рекомендованный MAX способ для тестов и учебного демо;
  для продакшена платформа советует Webhook (`POST /subscriptions`), это отдельная настройка.
- Аптайм/перезапуски: база и фото хранятся в `./data` (том в compose), так что
  объявления не теряются.
